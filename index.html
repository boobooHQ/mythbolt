What we do

Four ways in, one way of working

Every engagement ends the same way: a finding you can reproduce from the report alone, or a documented reason the surface held.

01

Web & API Testing

Authentication logic, access control, injection, and the seams between them. Full-surface coverage with a written record of what was tested, not just what was found.

02

Vulnerability Research

Protocol and parser work on telecom, embedded, and enterprise platforms. Where a patch fixed the proof-of-concept but not the vulnerability class, we find the variant.

03

Secure Code Review

Source-level audits with semantic analysis and manual review of the paths that matter — deserialization, entity resolution, authorization ordering, trust boundaries.

04

Adversary Simulation

Chained attack paths that reflect how a real intrusion unfolds: a low-severity primitive escalated, step by step, into the outcome that actually costs you something.

Writing on method

Notes from live engagements — mostly about how findings get missed, and the discipline that stops it happening twice.

Parsers12 min

Patching the proof, not the bug

A fix that closes the exact request in the report, and nothing adjacent to it, leaves the vulnerability class intact. On regression-testing the variant instead of re-running the original payload.

Read
Access control9 min

The gate that was never there

Bypassing a 401 and finding a route that never had a check are different bugs with different fixes. Most testing conflates them, and the second one is worth more.

Read
Method7 min

Read the body, not the status code

A 200 can carry an authorization error. A 401 on a path that does not exist tells you the gate is blanket, not route-specific. Status-only sweeps produce confident, wrong maps.

Read
Method6 min

Invisible is not absent

An interface that does not offer registration is not a server that refuses it. Disabled fields, unlinked flows, and deprecated versions all still answer when you ask them directly.

Tooling11 min

A tool exiting zero is not a completed scan

Four separate tools failed silently in a single engagement and every one of them returned success. Positive controls, artifact assertions, and why coverage counts belong in the report.

Writing the report the triager wants

About

A practice, not a scanner subscription

Mythbolt is an independent offensive-security practice working on web applications, APIs, distributed platforms, and embedded infrastructure.

Most security testing stops at the first thing that looks hardened. The interesting findings are usually one layer past that — in the disagreement between two components, in the version nobody deprecated properly, in the endpoint the interface stopped linking to but the server still answers.

Work is delivered as reproducible proof. Every report includes the exact requests, the expected and actual responses, the controls that rule out a false positive, and an honest account of what was tested and did not break. A clean result is a real result when it is earned.

Engagements run through public and private disclosure programmes as well as direct contract. If you want to talk about scope, the fastest route is LinkedIn or the address below.
